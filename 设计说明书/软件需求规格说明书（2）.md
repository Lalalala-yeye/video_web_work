### 3.2 需求概述

#### 3.2.1 目标

- **开发意图与应用目标**：开发名为“doinb”的视频播放与内容服务类网站，整合用户与权限管理、视频点播、直播、订阅、视频发布与编辑、评论与搜索等能力，解决课程实践与同类小型产品在“功能分散、流程不连贯、发布与观看体验割裂”等问题上的不足，使普通用户与内容发布者在一套界面内完成观看、互动、订阅与内容管理。

- **主要功能和流程**：用户完成注册登录后，可浏览与搜索视频、在线播放并记录历史；可进入直播列表观看直播；可订阅感兴趣的发布者或频道；发布者上传与维护视频；用户可在视频或直播相关内容下评论，并通过关键词检索视频/直播/频道等。数据经浏览器提交至服务端，由业务模块处理并读写数据库与媒体资源，再返回页面或流地址。

- **系统高层次图与关系**：本系统作为**独立 Web 产品**；在体系结构上分为用户界面层、服务处理层、数据管理层及与浏览器、媒体流/文件存储、数据库等的外部协作。设计上可借鉴主流视频网站的产品形态，并保留与后续扩展（如推荐、支付、第三方登录）对接的可能，但本版本不强制依赖其他业务系统。

#### 3.2.2 运行环境

- **硬件环境**：服务端可部署于课程组提供的云主机、实验室服务器或等同配置的虚拟机上，需支撑 Web 应用、关系型数据库及视频/直播相关资源存储与带宽需求。客户端无特殊硬件要求，支持常见 PC、平板与智能手机。

- **支持环境**：需关系型数据库支撑用户、内容、订阅、评论等数据的存储与查询；后端可部署在 Windows Server 或 Linux 等环境；用户通过现代浏览器访问，前端应兼顾主流浏览器兼容性与基本响应式布局。

#### 3.2.3 用户的特点

面向需要在线观看视频与直播、发表评论、订阅更新，以及需要上传和管理自己视频内容的用户。普通用户侧重操作路径短、页面清晰、加载与播放可接受；内容发布者侧重上传与编辑流程稳定、权限明确。整体要求界面易懂、错误提示清楚，便于课程演示与日常试用快速上手。

#### 3.2.4 关键点

**关键功能**

用户与权限管理功能：  
- 实现用户注册、登录、退出与个人信息查看、修改。  
- 基于角色分配权限，控制视频发布、直播与内容管理等入口的可见性与可用性。  

视频播放功能：  
- 支持在首页、推荐区与详情页浏览视频列表与元信息。  
- 提供在线播放、暂停、进度调节与清晰度切换（若实现），并记录与展示播放历史。  

直播功能：  
- 提供直播列表与进入直播观看能力。  
- 展示直播标题、状态等基本信息，并支持课程范围内允许的基础互动。  

订阅功能：  
- 支持用户对视频发布者或直播相关频道进行订阅与取消订阅。  
- 在订阅视图中展示订阅关系与关联内容更新或列表。  

视频发布与编辑功能：  
- 支持授权用户上传视频并填写标题、描述等元数据。  
- 支持对已发布视频进行信息修改、删除或状态管理（以上下架规则以设计为准）。  

评论与搜索功能：  
- 支持用户在视频或直播相关内容下发表评论并查看评论列表。  
- 支持按关键词检索视频、直播或频道等，并分页展示搜索结果。  

**关键技术和算法**：

- Web 开发技术：采用前后端分离模式，浏览器端负责页面与交互，服务端提供业务接口（具体前后端框架以设计实现为准）。  

- 数据库技术：采用关系型数据库（如 MySQL）持久化用户、视频与直播元数据、订阅关系、评论等核心业务数据。  

- 媒体与播放技术：完成点播与直播的媒资地址解析、访问权限校验与播放器控制；直播侧可采用推流/拉流方案或对接第三方直播服务（以实际方案为准）。  

- 检索与排序：基于关键词对标题、简介、作者等字段进行条件查询与结果排序，可结合索引或简单全文策略实现。  

- 安全与工程化措施：账号与敏感操作的基本防护、传输层安全（如 HTTPS）及访问控制要求与《软件开发计划》一致，在实现与测试阶段落实并记录。

#### 3.2.5 约束条件
 
- **质量与范围约束**：以“可运行、功能基本完整、文档配套”为主，性能与并发按课程级基线验收，不等同商业高并发产品。  
- **技术与方法约束**：在现有所学与常用工具范围内实现，采用模块化与迭代开发，先核心后完善。  
- **法律与伦理**：遵守数据保护与隐私相关政策，对用户数据采取基本保护措施；用户生成内容在课程范围内做基本管理，避免明显不当信息影响系统使用。

#### 3.3.2 软件子系统功能/对象结构

**用户与权限管理系统**  
- **注册流程**：用户填写注册信息并提交，服务端完成唯一性与格式校验，通过后写入用户数据并视设计返回自动登录或跳转登录页。  
- **登录与鉴权流程**：用户提交账号与凭据，服务端校验成功后建立会话或签发令牌，前端按角色展示导航与可访问菜单。  
- **个人资料与退出流程**：登录用户在个人中心查看/修改资料并保存；用户执行退出，服务端失效会话或令牌并回到未登录态。

**视频播放系统**  
- **浏览与推荐流程**：用户进入首页或推荐/列表页，系统按接口返回视频列表或推荐条目，点击进入视频详情。  
- **播放流程**：用户发起播放，服务端校验权限与资源后返回可播放地址或流信息，前端拉流/解码并支持暂停、进度、清晰度等控制。  
- **历史记录流程**：播放行为触发历史写入或更新，用户在历史页查询并按时间等维度展示。  

**直播系统**  
- **直播列表流程**：用户打开直播入口，系统返回当前或计划中的直播列表。  
- **观看流程**：用户选择某一直播进入房间页，系统加载展示信息与媒体流，用户离开或关闭时结束本次观看会话。  
- **互动流程**（以实际实现为限）：在允许的场景下用户发送互动信息，由服务端做基本校验、落库或广播后刷新展示。  

**订阅系统**  
- **订阅/取消流程**：用户在发布者、频道等对象上执行订阅或取消，服务端写订阅关系并返回最新状态。  
- **列表与更新展示流程**：用户打开订阅页，系统根据订阅关系拉取更新内容或列表并分页展示。  

**视频发布与编辑系统**  
- **上传与发布流程**：授权用户选择文件并填写标题、描述等，上传至存储后写入视频元数据与状态。  
- **编辑与管理流程**：发布者在管理页对已有视频做信息修改、删除或上下架，服务端按权限更新库内记录与资源状态。  

**评论与搜索系统**  
- **评论流程**：用户在目标内容下提交评论，服务端鉴权、过滤后写入，列表接口按时间等规则返回。  
- **搜索流程**：用户输入关键词并搜索，服务在可检索数据上执行查询，返回结果页并支持分页。

### 3.4 CSCI能力需求

#### 3.4.1 用户与权限管理能力

- 能力描述：为普通用户、内容发布者等提供注册、登录、退出、个人信息维护及基于角色的基本访问控制，防止未授权访问和敏感信息明显泄露。  

- 输入要求：用户标识（如用户名/邮箱/手机号，以实际实现为准）、密码、个人资料；登录/注销请求。  

- 处理要求：在常规操作下完成凭据校验与会话或令牌管理；对密码与关键字段采用安全存储与传输要求（见《软件开发计划》中安全与保密措施）；按角色控制发布、编辑、直播相关入口的可见性与可用性。  

- 输出要求：登录成功/失败与原因提示；个人资料展示与更新结果；与权限相关的功能入口是否可用。  

- 性能参数：登录与信息查询在课程环境下响应及时、可满足小组并发演示与基本访问。  

- 异常处理：账号或密码错误、会话失效、重复登录等应给出明确提示，避免泄露敏感信息；注册冲突、服务器不可达时给出可重试或稍后再试提示；敏感操作失败时记录日志（见 3.7）便于排查。  

- 连续运行需求：在计划部署与验收窗口内持续可用，计划内维护窗口外以课程作业可接受为目标，重要故障可短暂中断后恢复服务。  

#### 3.4.2 视频播放能力

- 能力描述：提供视频浏览、在线播放、播放控制、清晰度切换、播放历史等能力。  

- 输入要求：列表与推荐请求；视频标识；播放、暂停、拖曳进度、切换清晰度、查询历史等操作。  

- 处理要求：在权限与资源允许下解析播放地址与元数据；对访问做基本控制以保障播放稳定；历史记录可持久化并供用户查询。  

- 输出要求：页面展示视频信息、可播放流或播放错误说明；历史列表。  

- 性能要求：在课程项目条件下播放过程基本流畅、页面与播放控制响应较快。  

- 异常处理：资源不存在或已下架时提示“无法播放”类信息；网络或解码异常时给出可理解说明；列表无数据时展示空状态。  

- 连续运行需求：点播服务在部署期间应能支持连续多次播放与刷新，不因单次播放失败导致整站不可用。  

#### 3.4.3 直播能力

- 能力描述：提供直播内容列表、进入直播观看、直播信息与基础互动。  

- 输入要求：直播列表与详情请求；进入/离开直播间；允许的互动类输入（以实际实现为限）。  

- 处理要求：使直播页能加载直播信息与媒体流，减少明显卡顿与中断；对直播与访问做基本管理。  

- 输出要求：展示直播状态、可播放画面或错误说明。  

- 性能要求：直播页可正常加载，播放过程在课程环境下尽量保持连续可用。  

- 异常处理：推流/拉流或网络异常时提示并可返回列表；房间不存在或已结束时明确说明。  

- 连续运行需求：非单点实验场景下，列表与 rooms 接口在验收期间可反复进入退出；单路流异常不应拖死整个应用进程（以工程上合理为限）。  

#### 3.4.4 订阅能力

- 能力描述：支持用户对发布者或直播频道进行订阅/取消，并正确展示订阅关系与相关更新。  

- 输入要求：被订阅对象标识；订阅、取消、列表查询。  

- 处理要求：及时生效订阅关系；保证存取数据一致、避免错显或丢失。  

- 输出要求：订阅列表、状态变更确认、展示区域内容。  

- 性能要求：订阅与取消在合理时间内完成，列表展示准确。  

- 异常处理：目标对象不存在或已删除时提示失败；并发点击订阅/取消以最终一致为准并避免重复提示。  

- 连续运行需求：订阅关系数据在系统持续运行期间保持一致，服务重启后依赖数据库持久化恢复（与实现方式一致）。  

#### 3.4.5 视频发布与编辑能力

- 能力描述：供授权用户完成视频上传、元信息维护、已发布内容编辑与删除/管理。  

- 输入要求：视频文件与标题、描述等元信息；管理操作（编辑、删除、上下架以实际设计为准）。  

- 处理要求：仅具备权限的账号可发布与修改；提交与更新过程稳定、交互清晰。  

- 输出要求：上传/保存结果、内容管理列表、错误与校验提示。  

- 性能要求：信息提交、编辑、管理在课程可接受响应时间内完成。  

- 异常处理：格式不符、大小超限、权限不足、存储失败时给出原因与可重试或修正路径；大文件上传中断时尽量提示断点或重新选择（视实现）。  

- 连续运行需求：上传与编辑操作可多次提交，不因单次失败导致后台长期僵死；媒体与元数据状态可人工或自动恢复至一致。  

#### 3.4.6 评论与搜索能力

- 能力描述：对视频/直播相关栏目支持评论的发表与展示；支持基于关键词的搜索并展示结果。  

- 输入要求：评论内容、目标内容标识；搜索关键词、分页与筛选（若有）。  

- 处理要求：评论提交后列表更新；对评论做基本管理以防明显不当内容影响使用；搜索返回相关结果。  

- 输出要求：评论列表与状态；搜索结果页。  

- 性能要求：评论与搜索在课程环境下列表刷新与首屏出结果较快。  

- 异常处理：空结果、服务超时、含非法字符时提示清晰，搜索过程不崩溃；评论过于频繁或目标关闭评论时可拒绝并说明。  

- 连续运行需求：检索与评论接口在验收期可重复调用；评论 spam 或异常流量时以限流或降级展示为可选手段（设计阶段定）。  

### 3.5 CSCI外部接口需求



- **用户接口：** 通过Web浏览器（Chrome、Edge、Firefox等）进行交互。

- **硬件接口：** 无。本系统不直接与专用硬件设备（如读卡器、传感器、打印机等）交互。客户端运行所需的标准输入/输出设备（键盘、鼠标、显示器、扬声器）及网络设备由操作系统和浏览器管理，不构成本 CSCI 的硬件接口需求。
- **软件接口：** 
  - 对象存储/文件系统：视频文件存储采用本地文件系统或MinIO，通过HTTP API上传下载。
  - 数据库：通过JDBC/ODBC与MySQL交互。
- **通信接口：** HTTP/HTTPS协议，RESTful API。

### 3.6 CSCI内部接口需求


### 3.7 CSCI内部数据需求

1. **用户数据**  
   - **用户账号信息**：用户名/邮箱/手机号（以实际设计为准）、密码摘要或密文、注册与登录相关状态。  
   - **用户个人资料**：昵称、头像、简介等可展示字段。  
   - **角色与权限数据**：普通用户、内容发布者等角色及与菜单/接口相关的授权信息。  
   - **播放历史**：用户与已观看视频标识、观看时间或进度等（以实际表结构为准）。  

2. **视频数据**  
   - **视频元数据**：视频唯一标识、标题、描述、作者、分类或标签、时长、封面图地址。  
   - **媒资与状态**：媒体文件存储路径或 URL、发布/隐藏/删除等状态；多清晰度时各档地址或转码任务信息。  

3. **直播数据**  
   - **场次与房间信息**：直播标识、标题、所属频道或发布者、计划/实际起止时间。  
   - **流与展示信息**：拉流或播放地址、房间状态；若实现互动，可含互动消息或计数字段。  

4. **订阅数据**  
   用户与发布者、频道或直播间等被订阅对象之间的订阅关系、订阅时间与取消标记。  

5. **评论数据**  
   评论标识、关联的视频或直播等内容 ID、评论正文、发表时间、用户标识；用于排序、删除或屏蔽的辅助字段。  

6. **搜索与辅助数据**（可选）  
   为加速检索维护的索引表、分词结果或缓存键等，须与主业务数据可对应、可重建。  

7. **其他系统配置数据**  
   站点参数、功能开关、限流阈值等；操作日志、错误日志及审计所需条目。  

以上数据主要存放在数据库中，需要进行合理的设计和管理。对于数据库的需求包括但不限于：  

- **数据库类型**：关系型数据库，实现上可采用 MySQL 或课程环境规定的同类系统。  
- **数据库表结构设计**：表之间通过主外键或逻辑关联表达用户、视频、直播、订阅、评论等关系，满足第 3 章功能需求。  
- **数据库索引设计**：为列表查询、按用户查历史、按标题/作者搜索等常用条件建立合适索引，兼顾写入性能。  
- **数据库备份与恢复策略**：按课程/部署环境制定周期备份与简单灾难恢复办法，重要数据不依赖单点无备份。  

对于数据文件的需求可能包括：  

- **日志文件**：系统操作、错误、关键安全事件等日志，按大小或日期切割并保留合理周期。  
- **配置文件**：应用端口、数据库连接、媒体根路径等，不含明文密码，敏感项使用环境变量或密钥管理。  
- **用户上传的媒体文件**：大文件以对象存储或指定目录管理，与数据库元数据一致。

### 3.11 CSCI环境需求

**硬件环境**  
- **服务端**：至少一台可运行 Web 与数据库的计算机或虚拟机/云主机，用于部署应用服务与关系型数据库；配置应满足开发计划中的并发与基本性能预期，并预留日志与媒体存储空间。  
- **数据库**：可独立或与应用同机部署，需满足所选用数据库的最低硬件建议。  
- **客户端**：以常见 PC 与移动设备为主，无特殊外设要求；能运行现代浏览器、具备音视频解码与网络访问能力。  
- **网络**：局域网或互联网环境可访问服务端；与 HTTPS、推流/拉流（若使用直播/点播协议）的带宽和稳定性相适应。  
- **开发端**：项目组成员个人计算机，用于编码、联调、版本管理与课程要求的本地/测试环境。  

**软件环境（操作系统与支撑软件）**  
- 服务器操作系统可选用 Windows Server 或主流 Linux 发行版之一，以实际部署与课程环境为准。  
- 用户终端采用 Windows、macOS、Android、iOS 等常见系统均可，需安装或内置现代浏览器。  
- 需安装与运行所选用应用服务器/运行时、关系型数据库管理系统、可能用到的流媒体/对象存储或 CDN 等组件，版本在部署文档中说明。  
- 开发计划提出的安全要求（如 HTTPS、防火墙/入侵检测在可选用条件下）在目标环境中应可配置。

### 3.13 软件质量因素

在课程项目与《软件开发计划》约束下，对“doinb”CSCI 提出下列软件质量要求（以定性为主，关键指标在能力需求与测试中体现）。

- **功能性**：应实现用户与权限、视频播放、直播、订阅、发布与编辑、评论与搜索等已约定核心能力，行为与《软件开发计划》及本 SRS 一致，无未说明的重大功能缺失。  
- **可靠性**：在典型操作下产生正确、一致结果；对常见异常（网络、鉴权、资源不存在）有明确提示，避免未处理崩溃导致数据明显损坏。  
- **可维护性**：需求与《软件开发计划》要求代码结构清晰、命名可读、关键逻辑有适度注释，便于结课后改进与问题修复。  
- **可用性**：在部署与课设演示时段内，系统可被正常访问与操作；对关键功能响应时间在课程可接受范围（见 3.4）。  
- **灵活性**：宜采用模块化与迭代实现方式，使后续能扩展清晰度、推荐、审核策略等，而不必整体推翻架构。  
- **可移植性**：服务端与数据层在常见 Web 与数据库环境下可重新部署；客户端不绑定单一专有客户端形态。  
- **可重用性**：鼓励抽取公共组件与接口，便于在站内模块间复用及参考同类产品模式（如《软件开发计划》所述）。  
- **可测试性**：主要功能可构造输入并验证结果；测试能覆盖主流程、常见异常与主要界面交互。  
- **易用性**：界面与交互清晰，满足普通用户观看、评论、订阅与发布者管理内容的基本易用性（与计划书中用户需求一致）。
