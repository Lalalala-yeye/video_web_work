## 结论（答辩用两三句）

- 同一脚本、同一台机器。登录两边都约 32～33 req/s、均时约 1.5s，被 BCrypt 卡住，拆不拆服务几乎一样，错误率都是 0。
- 列表 / 搜索单体吞吐明显更高（约 645 / 474 vs 116 / 83 req/s），P50 约 21ms / 20ms vs 43ms / 89ms。微服务多一跳网关 + 六个 JVM，单机对比本来就会吃亏。
- 单体列表、搜索第 2～3 轮 P95 掉到 30ms 量级，第 1 轮仍约 2s，是 Windows Docker 端口转发长尾；微服务 P95 三轮都在 2s 附近。
- 微服务内存合计约 2.0 GiB，单体约 1.0 GiB。本次单体是新库 seed，微服务是已有数据卷，列表/搜索吞吐不能当成「同等数据量」的绝对比。
