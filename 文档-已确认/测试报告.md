# 测试报告（2）

> 本文档登记 `.github/workflows/ci.yml`里实际执行的测试用例。   

## 1 引言

### 1.1 目标

说明 doinb 平台在 CI 中自动化测试的具体测试用例情况和测试结果。

### 1.2 背景

系统为 Spring Boot + Vue 3。每次推代码都会经过测试门禁检测。

### 1.3 范围（与 CI job 一一对应）

按 V 模型组织。组件级集成测试不做。

| V 模型 | 本项目做法 | CI job | 用例数 | 门禁 |
| ------ | ---------- | ------ | ------ | ---- |
| 单元测试（详细设计 ↔ 对象） | `*ServiceImplTest`：Mock Mapper，对着系统操作 OP-001～OP-044 测业务规则 | `backend-test` | 179 | 是 |
| （随单元一起跑，不是组件集成） | `*ApiTest` MockMvc：无 MySQL，校验 HTTP 契约 | 同上 | 80 | 是 |
| 集成测试（概要设计 ↔ 组件） | **不做** | — | 0 | — |
| 系统测试（系统需求 ↔ 用例基本/扩展流程） | Newman 打已启动的后端（真 MySQL），覆盖注册登录等主路径与异常路径 | `postman` | 15 | 是 |
| 验收测试（用户需求 ↔ GUI） | Selenium：前端+后端都起，对着页面点 | `e2e` | 54 | 否 |
| **合计** | | | **328** | 门禁 **274** |

更全的用例级接口用例（59 条，H/U/V/C/R/F/S/L/N/M/A）见《测试报告》第 4 节，可手工对后端容器补跑；CI Newman 是其中自动化冒烟子集。

## 2 测试计划

### 2.1 目的

用自动化重复验证：对象级业务规则（单元）、系统操作 HTTP 契约（MockMvc，非组件集成）、用例级真库接口（系统测试 / Newman）、GUI 主路径（验收 / E2E）。

### 2.2 测试项

| 层次 | CI job | 字母/前缀 |
| ---- | ------ | --------- |
| 单元（对象级） | backend-test | UTU/UTP/UTV/UTA/UTC/UTR/UTF/UTS/UTL/UTN/UTM |
| MockMvc（系统操作契约） | backend-test | IT001～IT080 |
| 系统测试 Newman | postman | PM-H000 等，对应集合请求名 |
| 验收测试 E2E | e2e | ESE01～ESE05 |

**编号规则**：Newman 请求名沿用集合里的 H000/U000 等，本报告加前缀 `PM-` 。单元 `UT*`，MockMvc `IT*`，E2E `ESE*`。

### 2.3 测试方法

1. **单元**：JUnit 5 + Mockito，不启 Spring、不连 MySQL。
2. **MockMvc**：`@WebMvcTest` 标签写在 Controller。
3. **Newman**：使用 MySQL 8、执行 `database/database.sql`、启动 `application-ci` 后端，再用 Newman 跑集合；用户名为 `ci_`+时间戳，可重复跑。`--bail` 遇失败即停。
4. **E2E**：再起库+seed、后端、Vite 8787、Chrome，依次跑 5 个脚本。

### 2.4 测试通过准则

- 单元/MockMvc：JUnit 断言全部符合预期。
- Newman：每条请求的 `pm.test` 全部通过。
- E2E：脚本 `assert` / 预期文案全部满足。
- 接口统一结构：`{code, message, data}`。

### 2.6 测试前准备

本地对齐 CI：

```bash
# 1) 单元+MockMvc
cd backend && ./mvnw -B test

# 2) Newman（需 MySQL + 后端 ci profile）
npx --yes newman@6 run postman/doinb.postman_collection.json -e postman/doinb.ci.postman_environment.json --bail

# 3) E2E（后端8081 + 前端8787 + Chrome）
cd web && $env:E2E_HEADLESS="1"; npm run e2e:ci
```
