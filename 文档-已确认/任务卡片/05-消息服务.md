# 任务卡：消息服务

| 项 | 内容 |
|---|---|
| 模块 | `services/doinb-message`（端口 **8086**） |
| 负责人 | （填写） |
| 用例 | UC-13 通知、UC-14 私信 |
| 测试模块 | M8、M9 |
| 从哪拷 | `NotificationController` `MessageController` `NotificationServiceImpl` `MessageServiceImpl` 及 Mapper |

## 功能

通知列表、未读数、标已读；打开私信会话、拉会话、发送。  
**优先实现** `POST /internal/notifications`，视频和互动卡在等你。

## 库表（只动这些）

| 表 | schema（目标） |
|---|---|
| `notifications` | `doinb_msg` |
| `dm_rooms` | `doinb_msg` |
| `dm_messages` | `doinb_msg` |

`user_id` / `actor_id` / `peer` 只存 ID。列表里的昵称调用户内部接口；审核通过类通知展示名仍用 `doinb`（见现网 `SYSTEM_ACTOR_NAME`）。

## 对外接口（路径禁止改）

`GET /notification/list` `GET /notification/unread-count` `POST /notification/read`  
`POST /message/room/open` `GET /message/room/get` `POST /message/send`  
`GET /health`

全部需要登录（`X-User-Id`）。

## 你提供给别人（桩在 `internal/`，请尽快落库）

| 调用方 | 方法 | 路径 |
|---|---|---|
| 视频（审核通过）、互动（点赞） | POST | `/internal/notifications` |

体见《内部接口契约》第 5 节。`userId == actorId` 直接 200 不写库。私信产生的通知在 **本服务内部** 写，不要 HTTP 调自己。

## 你要调用谁

| 何时 | 目标 | 方式 |
|---|---|---|
| 通知/私信展示昵称头像 | 用户 `GET /internal/users?ids=` | 同步 HTTP |

**不要** 再查 `videos` / `comments`。`linkPath` 用调用方传入的；缺省时按 type 拼：`/video/{refId}` 或 `/messages/{refId}`。

## 通信方式

同步 HTTP。别人调你内部接口必须带 `X-Internal-Token`（过滤器已做）。

## 验收

- N000～N021、M000～M020 行为与单体一致
- `curl` 带内部令牌 POST 一条通知能在列表里看到
- 发私信同时出现 type=3 通知
- 不写 `videos` `comments` `users`
