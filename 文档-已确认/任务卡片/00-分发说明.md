# 任务卡片怎么分

每人发 **一张服务卡片** + 本文 + [内部接口契约](../内部接口契约.md)。不要只说「你拆视频」。

## 你（骨架）已经做完的

- `services/` 多模块工程能编译、能分别启动
- 网关 8080：验 JWT、按路径转发、拦截 `/internal`、空搜索聚合
- 五服务：`/health` + 内部接口桩
- 统一头、统一 `{code,message,data}`、`ServiceClient`

组员在对应模块里 **填业务**，不要另起仓库、不要改对外路径。

## 建议顺序

1. **用户服务**先能注册/登录并发 JWT（其它人联调依赖 token）
2. **消息服务**先能 `POST /internal/notifications` 落库
3. 视频、直播、互动三人并行
4. 网关搜索三个内部接口有数据后即可验收 UC-12

人少可合并：直播+消息，或你兼网关。

## 每人必读

| 文件 | 用途 |
|---|---|
| 本卡片 | 自己的边界 |
| [内部接口契约](../内部接口契约.md) | 和别人怎么调 |
| [服务接口清单](../服务接口清单.md) | 对外 HTTP，路径禁止改 |
| [数据表归属方案](../数据表归属方案.md) | 只动自己的表 |
| 单体 `backend/src/main/java/...` | **拷逻辑**，不要复制整个工程 |

## 共用禁止项

- 不准 JOIN 别人的表，只存对方业务 ID
- 不准在下游再验 JWT、不准每次回问用户服务「这人登录了没」
- 不准把 `/internal` 暴露给前端
- 媒体推拉流仍走 SRS，Java 只管房间元数据
- 第一期可共用一台 MySQL，逻辑上按卡片里的 schema 分开即可
