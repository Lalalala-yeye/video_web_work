## 1 引言

### 1.1 编写目的

本文档在《软件概要设计说明书》的基础上，细化了 **doinb 视频播放与内容服务平台** 各子系统与功能模块的设计，便于开发团队理解系统各部分的详细功能、处理逻辑与界面交互，并作为编码实现与测试的依据。

预期读者：项目开发小组的开发人员、测试人员及项目管理人员。

### 1.2 背景

- **待开发软件系统名称**：doinb 视频播放与内容服务平台  
- **任务提出者**：软件工程课程组  
- **开发者**：第 9 组项目开发小组  
- **用户**：普通视频观众、内容发布者、系统管理员  
- **运行该软件的计算站（中心）**：课程组提供的云主机或实验室服务器；用户通过 PC、平板、智能手机上的现代浏览器以 Web 方式访问

## 3 功能模块设计

> **模块编号说明**：本节 **M1～M10** 与 SRS「关联子系统」、需求追溯矩阵 2.1、测试报告模块字母一致。

### 3.1 用户与权限管理模块

| 项目 | 说明 |
| :--- | :--- |
| **模块编号** | M1 |
| **模块名称** | 用户与权限管理模块 |
| **输入** | 注册信息（用户名、密码、确认密码）；登录凭据；资料修改；头像文件；退出登录 |
| **处理** | **注册**：校验两次密码、用户名唯一后写入 `users`。**登录**：校验凭据后签发 JWT。**资料/头像**：鉴权后更新昵称、简介、头像。**权限**：按 `role`（发布者/管理员）控制创作中心与后台入口 |
| **算法描述** | 注册：查重 → 密码哈希 → `INSERT`。登录：查用户 → 比对哈希 → 生成 JWT。鉴权：解析 Authorization Bearer Token → 校验签名与过期 → 比对角色 |
| **输出** | `{code,message,data}`；成功时含 token 与用户信息 |

### 3.2 视频浏览与播放模块

| 项目 | 说明 |
| :--- | :--- |
| **模块编号** | M2 |
| **模块名称** | 视频浏览与播放模块 |
| **输入** | 列表分页；视频 ID；播放进度；上传文件与标题/可见性；编辑与举报参数 |
| **处理** | **浏览播放**：查询已发布视频，返回播放地址。**历史**：登录用户写入/更新 `play_history`。**上传编辑**：公开投稿进入待审（status=0），私密可直接仅自己可见；作者可改元数据、可见性、删除。**举报**：对已发布视频写入举报记录 |
| **算法描述** | 列表：`status=已发布` + 分页。上传：校验标题与文件 → 落盘 `uploads/` → `INSERT videos`。缺文件时 Controller 将 `file` 视为可选，Service 返回 `code=400`「请上传视频文件」 |
| **输出** | 视频列表/详情、播放历史、上传与编辑结果 |

### 3.3 评论模块

| 项目 | 说明 |
| :--- | :--- |
| **模块编号** | M3 |
| **模块名称** | 评论模块 |
| **输入** | targetId、targetType（1=视频 2=直播）、content、分页 |
| **处理** | 鉴权后校验目标存在（视频已发布，或直播间已开播）→ 写入 `comments` → 按时间倒序列表 |
| **算法描述** | `INSERT comments`；列表按 `(target_id, target_type)` 分页 |
| **输出** | 发表结果与评论分页 |

### 3.4 赞踩互动模块

| 项目 | 说明 |
| :--- | :--- |
| **模块编号** | M4 |
| **模块名称** | 赞踩互动模块 |
| **输入** | videoId 或 commentId；reaction（1=赞 -1=踩 0=取消） |
| **处理** | 校验目标 → 写入或更新 `video_reactions` / `comment_reactions` → 新点赞且非本人时调用通知模块 |
| **算法描述** | 同一用户对同一目标仅保留一种状态；取消则删除记录并重算计数 |
| **输出** | 操作结果及 likeCount / dislikeCount / userReaction |

### 3.5 关注订阅模块

| 项目 | 说明 |
| :--- | :--- |
| **模块编号** | M5 |
| **模块名称** | 关注订阅模块 |
| **输入** | 目标用户 ID；关注/取消；动态分页 |
| **处理** | 在 `subscriptions` 插入或删除关系；Feed 聚合已关注作者的公开视频与正在直播的房间 |
| **算法描述** | 禁止关注自己；`(follower_id, target_id)` 唯一；动态 `JOIN` 后按时间分页 |
| **输出** | 关注状态、关注列表、订阅动态 |

### 3.6 搜索模块

| 项目 | 说明 |
| :--- | :--- |
| **模块编号** | M6 |
| **模块名称** | 搜索模块 |

### 3.7 直播模块

### 3.8 通知模块

| :--- | :--- |

| **模块名称** | 通知模块 |

| **处理** | 查询当前用户通知；返回未读数；标记已读。写入由 M4/M9/M10 等调用 |

| **算法描述** | 校验管理员 → 校验视频状态 → `UPDATE status`；通过时 `notifyVideoApproved` |

## 4 界面设计

### 4.1 外部界面设计

本节描述系统与外部实体（用户浏览器、数据库、对象存储等）之间的功能与数据接口。

#### 4.1.1 视频播放页面

**功能接口：**

- **浏览视频**：用户通过首页、推荐区或分类入口请求视频列表。  
- **播放视频**：用户点击某视频进入详情页并发起播放，系统返回流地址与元数据。  
- **记录历史**：登录用户在播放过程中上报进度，系统更新播放历史。

**数据接口：**

- **视频信息库（`videos`）**：提供标题、封面、作者、状态、存储路径等。  
- **播放历史库（`play_history`）**：存储用户 ID、视频 ID、进度与更新时间。  
- **对象存储/文件系统**：提供视频文件与封面的实际读写。

#### 4.1.2 直播观看页面

**功能接口：**

- **直播列表**：用户打开直播入口，获取当前或计划中的直播间列表。  
- **进入观看**：用户选择直播间，加载直播信息与拉流地址。  
- **基础互动**：在允许场景下发送弹幕或评论类互动信息。

**数据接口：**

- **直播间库（`live_rooms`）**：提供标题、主播、流密钥、是否直播中。  
- **评论/互动库（`comments` 或扩展表）**：存储直播场景下的互动记录。  
- **流媒体服务**：提供推流/拉流地址（自建或第三方，以实现为准）。

#### 4.1.3 视频发布与管理页面

**功能接口：**

- **上传视频**：发布者选择文件并填写标题、描述、封面等，提交上传。  
- **编辑元数据**：对已发布视频修改标题、描述、封面等。  
- **内容管理**：对视频执行删除或上下架操作。

**数据接口：**

- **视频信息库（`videos`）**：持久化元数据与状态。  
- **对象存储**：接收视频与封面二进制文件。  
- **用户库（`users`）**：校验发布者身份与角色。

#### 4.1.4 评论与赞踩页面（M3 / M4）

**功能接口：**

- **发表/查看评论**：在视频或直播详情下提交并分页加载评论。  
- **赞踩**：对视频或评论点赞、点踩或取消。

**数据接口：**

- **comments**、**video_reactions**、**comment_reactions**。

#### 4.1.5 搜索页面（M6）

**功能接口：**

- **关键词搜索**：返回视频、直播、用户三类结果。

**数据接口：**

- **videos**、**live_rooms**、**users**。

#### 4.1.6 通知与私信页面（M8 / M9）

**功能接口：**

- **通知**：列表、未读数、标记已读。  
- **私信**：打开会话、发送与查看消息。

**数据接口：**

- **notifications**、**dm_rooms**、**dm_messages**。

#### 4.1.7 管理审核页面（M10）

## 5 异常处理设计

### 5.1 出错信息管理

系统运行中可能出现的错误与异常包括：

1. 用户输入格式错误（空字段、密码过短、非法字符等）。  
2. 鉴权失败（Token 过期、未登录访问受保护接口）。  
3. 数据库连接失败或 SQL 执行异常。  
4. 媒体资源不存在、已下架或存储服务不可用。  
5. 上传文件超限、格式不支持或网络中断。  
6. 搜索无结果、评论过于频繁等业务逻辑异常。

**处理方法和策略：**

1. 前后端双重校验输入，返回统一错误码与友好中文提示，引导用户修正。  
2. 鉴权失败返回 401/403，前端跳转登录页，不暴露堆栈信息。  
3. 数据库操作使用 try-catch，记录错误日志，向用户展示"服务暂时不可用，请稍后重试"。  
4. 播放/拉流失败时提示"无法播放"并记录资源 ID，便于运维排查。  
5. 上传模块校验大小与 MIME，失败时保留已填元数据（若可行）并支持重新选择文件。  
6. 业务异常使用明确文案（如"该视频已下架""请先登录"），关键错误写入操作日志表或文件日志。

### 5.2 故障预防与补救

**可能导致系统故障的因素：**

1. 网络波动导致接口超时或视频卡顿。  
2. 数据库存储空间不足或连接池耗尽。  
3. 对象存储或流媒体节点异常。  
4. 代码缺陷导致未捕获异常。

**预防措施：**

1. 使用 Nginx 反向代理与健康检查；前端对超时请求重试（幂等读操作）。  
2. 定期备份 MySQL，监控磁盘与连接数；为常用查询字段建立索引。  
3. 大文件与点播/直播流分离部署，课程演示环境预留足够带宽与空间。  
4. 迭代开发与分模块测试，合并前进行集成测试。

**补救措施：**

1. 网络异常时提示用户检查网络并支持手动刷新。  
2. 数据库异常时切换只读提示或重启服务，从备份恢复（严重情况）。  
3. 存储不可用时降级为"暂不可播放/上传"，避免整站崩溃。  
4. 记录异常堆栈，修复后发布补丁并执行回归测试。

### 5.3 系统维护设计

**系统维护计划：**

1. 定期备份数据库与关键配置，清理临时上传碎片。  
2. 根据访问日志评估慢查询与热点接口，优化索引与缓存策略。  
3. 在课程验收前进行安全自查（弱口令、默认密钥、HTTPS 配置等）。

**问题处理策略：**

1. 用户或测试人员反馈问题后登记（问题描述、复现步骤、模块编号）。  
2. 按严重程度分级处理：阻塞性缺陷优先修复并再测试。  
3. 对影响演示的故障（无法登录、无法播放）启动紧急修复流程，并在文档中记录变更说明。

## 6 性能优化和安全设计

### 6.1 数据存储安全性考虑

- **数据加密**：用户密码采用 BCrypt 等单向哈希存储，不以明文保存。  
- **访问控制**：数据库账号按最小权限配置，应用层通过连接池访问，禁止公网直接暴露数据库端口。  
- **备份**：定期备份用户与业务数据，防止误删或损坏。

### 6.2 数据传输安全性考虑

- **加密传输**：生产或演示环境宜启用 HTTPS，防止 Token 与密码在传输中被窃听。  
- **完整性**：接口采用 JSON 等格式并校验 Content-Type；重要写操作可记录请求摘要便于审计。

### 6.3 数据访问安全性考虑

- **身份验证**：除注册、登录、公开列表等接口外，敏感操作需在请求头携带有效 JWT。  
- **权限控制**：发布、编辑、直播开播等接口校验角色（发布者/管理员）。  
- **审计日志**：记录登录失败、权限拒绝、上传失败等事件，便于发现异常访问。

### 6.4 性能优化考虑

- **数据库索引**：为 `users.username`、`videos.author_id`、`videos.status`、`comments.target_id`、`subscriptions.follower_id` 等高频查询字段建立索引。  
- **数据缓存**：对首页推荐列表、热门直播列表等只读数据可使用内存缓存（如 Redis，若实现）降低数据库压力。  
- **静态资源**：视频、封面等大文件通过 Nginx 或对象存储直出，减轻应用服务器带宽压力。  
- **分页与懒加载**：列表与搜索结果统一分页，评论与互动区按需加载，避免单次返回过大数据集。  
- **响应时间目标**：普通查询接口在课程环境下力争 200ms 内返回（与概要设计一致）。
