# doinb 内部接口契约

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 编制日期 | 2026-08-31 |
| 用途 | 拆进程后服务间调用；网关不对浏览器转发这些路径 |
| 配套 | [微服务划分图](./微服务划分图.md) · [服务接口清单](./服务接口清单.md) · [数据表归属方案](./数据表归属方案.md) · [任务卡片](./任务卡片/00-分发说明.md) |

对外路径仍走网关 **8080**（切流后改 8081），与《服务接口清单》一致。本节只写 **服务之间** 的同步 HTTP。

## 1 通信约定

| 项 | 约定 |
|---|---|
| 协议 | HTTP + JSON，同步请求，课设不上消息队列 |
| 返回 | `{ "code": 200, "message": "OK", "data": ... }` 与单体相同 |
| 内部令牌 | 请求头 `X-Internal-Token`，全组同一值（默认 `doinb-internal-dev-token`，环境变量 `DOINB_INTERNAL_TOKEN`） |
| 登录用户 | 网关验 JWT 后注入 `X-User-Id`、`X-User-Role`（`user` / `admin`）。下游 **不要再解析 JWT、不要回问用户服务鉴权** |
| 浏览器 | 打 `/internal/**` 一律 403（网关拦截） |
| 调用工具 | 注入 `com.doinb.common.client.ServiceClient` |

端口：用户 8082、视频 8083、直播 8084、互动 8085、消息 8086。

## 2 用户服务提供

| 方法 | 路径 | 调用方 | 说明 |
|---|---|---|---|
| GET | `/internal/users/{id}` | 互动（关注目标是否存在）；其它需要昵称时 | `data` 为 `UserDTO`；不存在 `code=404` |
| GET | `/internal/users?ids=1,2,3` | 视频/直播/互动/消息拼昵称 | `data` 为 `UserDTO[]`，缺的 id 跳过 |
| GET | `/internal/search/users?keyword=&limit=` | 网关 `/search` | `data` 为 `UserDTO[]`，按用户名/昵称模糊 |

`UserDTO`：`id, username, nickname, avatar, role, bio`（与单体一致，无密码）。

## 3 视频服务提供

| 方法 | 路径 | 调用方 | 说明 |
|---|---|---|---|
| GET | `/internal/videos/{id}` | 互动发评论前确认目标 | `data` 含至少 `id, title, authorId, status`；不存在 404 |
| GET | `/internal/videos/by-authors?authorIds=1,2&limit=100` | 互动订阅动态 | 仅 `status=1` 已发布，按时间倒序，`data` 为 `VideoDTO[]` |
| GET | `/internal/search/videos?keyword=&limit=` | 网关 `/search` | 仅已发布，标题模糊 |

## 4 直播服务提供

| 方法 | 路径 | 调用方 | 说明 |
|---|---|---|---|
| GET | `/internal/lives/{id}` | 互动发弹幕 / 拉弹幕 | `data` 含 `id, title, anchorId, isLive, sessionStart`；不存在 404 |
| GET | `/internal/lives/by-anchors?anchorIds=1,2&limit=50` | 互动订阅动态 | 仅 `isLive=true`，`data` 为 `LiveRoomDTO[]` |
| GET | `/internal/search/lives?keyword=&limit=` | 网关 `/search` | 标题模糊 |

弹幕：房间不存在 → 互动返回 404；存在但未开播 → 互动返回 400「直播间未开播，无法发送弹幕」。

## 5 消息服务提供

| 方法 | 路径 | 调用方 | 说明 |
|---|---|---|---|
| POST | `/internal/notifications` | 视频（审核通过）、互动（点赞） | 写入 `notifications` |

请求体 `CreateNotificationRequest`：

```json
{
  "userId": 12,
  "type": 4,
  "actorId": 1,
  "refId": 30,
  "preview": "你的视频《标题》已通过审核并公开发布",
  "linkPath": "/video/30"
}
```

`type`：1=视频被赞 2=评论被赞 3=私信 4=审核通过。  
`linkPath` 可选；调用方尽量带上，消息服务就不必再查视频/评论。  
自己给自己操作（`userId == actorId`）应直接忽略，返回 200。

私信通知由消息服务内部写，不必再 HTTP 调自己。

## 6 谁调用谁（对照划分图 2.2）

| 发生的事 | 调用 |
|---|---|
| 管理员审核通过 | 视频 → `POST` 消息 `/internal/notifications`（type=4） |
| 视频/评论点赞 | 互动 → 同上（type=1 或 2） |
| 发送私信 | 消息服务内部写会话 + 通知 |
| 发表评论 | 互动 → `GET` 视频或直播 `/internal/.../{id}` |
| 关注某人 | 互动 → `GET` 用户 `/internal/users/{id}` |
| 订阅动态 | 互动 → 视频 `by-authors` + 直播 `by-anchors`；昵称可再调用户 `?ids=` |
| 关键词搜索 | 网关并行调三个 ` /internal/search/* ` |

互动服务 **不** 对他人提供内部接口（本期）。

## 7 代码位置

桩已写在各服务 `internal/` 包，组员改实现、不要改路径和入参名。  
DTO：`services/doinb-common/src/main/java/com/doinb/common/dto/`。
