## 1 简介

### 1.1 目的

该软件需求规格说明书（以下简称“说明书”）属于“doinb 视频播放与内容服务平台”项目。本说明书旨在明确并形式化项目需求，定义平台的功能和行为，以便与课程组及项目干系人进行需求确认，并指导之后的软件设计、编码实现、测试和部署等过程。

此文档的预期受众包括客户、开发人员、测试人员和其他相关利益相关者。

用例编号与《需求追溯矩阵》保持一致（UC-01～UC-15），需求、设计、代码、测试均按本编号追溯。每个业务场景均给出用例描述与系统顺序图。

### 1.2 范围

#### 1.2.1 软件名称

doinb 视频播放与内容服务平台（doinb Video Platform）

#### 1.2.2 软件描述

doinb 是一个在线视频点播与内容服务系统，旨在帮助用户在同一套界面内完成观看、互动、订阅与内容管理。本软件大致提供以下功能：

- **访客**：注册账号、登录系统。
- **注册用户**：浏览与播放视频、评论与赞踩、关注作者、搜索、私信与通知、进入直播间观看与评论。
- **作者**：在注册用户能力之上上传视频、编辑稿件、创建与开关播直播间。
- **管理员**：审核待发布视频、处理视频举报、管理平台内容。

#### 1.2.3 应用场景

该软件主要用于课程实践与小组演示，帮助解决同类小型视频产品“功能分散、流程不连贯、发布与观看体验割裂”等问题；提供一个可注册登录、上传与审核视频、在线播放、互动关注、搜索、私信通知及直播房间管理的完整业务闭环。

## 2 产品整体描述

### 2.1 产品描述

本产品是一个在线视频播放与内容服务平台。一方面，用户可以在该平台上浏览、搜索和在线播放视频，并记录播放历史；另一方面，作者可以上传与维护视频、管理直播间，管理员对内容进行审核与举报复审；用户还可以评论、赞踩、关注作者、收发私信与系统通知。

本产品是一个完全独立的 Web 系统，无需依赖其他业务系统。直播真实画面依赖可选的外部推流工具与 SRS 等流媒体服务，本版本观众端直播画面为演示占位，不作为核心验收项。

### 2.2 产品功能

本产品的功能根据使用者的属性不同有所不同，各类使用者的主要功能如下：

**访客：**

- 注册用户：访客通过填写注册表单注册成为该系统的用户。
- 登录：访客通过输入用户名和密码登录，并转换为注册用户属性。

**注册用户：**

- 操作个人信息：用户可以查看或修改自己的个人信息、头像，并可修改密码、退出登录、切换本地多账号。
- 浏览与播放视频：用户可以浏览已发布视频列表、进入详情页在线播放，并查看播放历史。
- 评论与赞踩：用户可以对视频发表评论（含表情），并对视频或评论进行赞、踩。
- 关注与订阅动态：用户可以关注作者，并在订阅页查看其最新视频。
- 私信与通知：用户可以与其他用户私信，并查看系统通知（点赞、私信、审核结果等）。
- 关键词搜索：用户可以按关键词检索视频、用户和直播。
- 进入直播间：用户可以查看直播列表、进入直播间并发表直播评论。
- 举报视频：用户可以对违规视频提交举报。

**作者：**

- 上传与管理视频：作者可以上传视频与封面、填写标题简介与可见性，编辑或删除自己的稿件。
- 管理直播间：作者可以创建直播间并执行开播、停播。

**管理员：**

- 登录：通过具备管理员角色的账号登录，并获得后台权限。
- 审核视频：管理员可以查看待审列表、预览视频并执行通过或驳回。
- 举报复审：管理员可以查看举报列表并对被举报视频进行处置。
- 退出登录：管理员可以退出登录状态并变成访客属性。

### 2.3 用户特征

本产品的预期用户为具备基本电脑和网络使用能力的人群，包括课程组师生与演示观众。普通用户侧重操作路径短、页面清晰、加载与播放可接受；作者侧重上传与编辑流程稳定、权限明确；管理员侧重待审与举报处理路径清楚。整体要求界面易懂、错误提示清楚，便于课程演示与日常试用快速上手。

### 2.4 约束

本产品开发的约束如下：

a) 监管政策：本产品的存储内容以及互动内容都将遵守相关的监管政策和法律法规。  
b) 硬件限制：本产品应能在连接网络的基础上，在各种常见计算机运行。  
c) 与其他应用程序的接口：本产品目前与其他业务系统无接口需求；直播推流可选用 SRS 等外部流媒体服务。  
d) 并行操作：多名用户可同时注册登录、播放、评论、点赞；作者与管理员可同时进行上传与审核。  
e) 审核职能：新上传视频默认进入待审核，由管理员人工审核；用户可举报违规视频。  
f) 控制功能：系统按角色控制发布、直播与管理入口；上传文件大小上限为 500MB。  
g) 高级语言要求：前端主要采用 Vue 3、JavaScript；后端主要采用 Java（Spring Boot）。  
h) 信号握手协议：TCP/IP。  
i) 可靠性需求：本产品应具备一定的可靠性和稳定性，不应该在正常情况下出现崩溃现象，应确保用户正常使用。  
j) 应用的关键性：本产品为非关键应用（课程实践系统）。  
k) 安全和安保方面的考虑：本产品应保护用户个人隐私，尤其是个人密码。密码以哈希存储，管理员不能查看明文密码。

### 2.5 假设和依赖

- 该平台的主要用户群体为课程实践参与者与演示观众。
- 平台需要支持在主流浏览器（Chrome、Edge、Firefox 等）和主流电脑上运行。
- 平台需要遵守相关的网络发言规范以及上传文件的规范。
- 平台需要提供审核功能，新视频须经管理员审核后方可进入公开列表。
- 平台的服务器和设备上，需要满足一定的硬件要求，例如处理器性能、内存容量、网络带宽等。
- 直播真实推流依赖 OBS 等工具及可选的 SRS 服务，不作为本版本核心验收范围。

### 2.6 需求分配

- **1.0 版本（本版本）**：实现用户注册登录、视频上传与审核发布、视频浏览播放、评论赞踩、关注订阅、私信通知、关键词搜索、直播房间管理、举报与管理员复审。
- **2.0 版本**：完善直播真实推流与播放、AI 审核与以图搜视频等扩展能力。
- **3.0 版本**：根据用户需求做出针对性改进（推荐、第三方登录等）。

**UC-01 用户注册**

| 项目 | 内容 |
|---|---|
| 用例名称 | 用户注册 |
| 用例编号 | UC-01 |
| 需求ID | REQ-01 |
| 关联子系统 | M1 用户与权限管理 |
| 关联操作 | OP-002 `POST /user/account/register` |
| 参与者 | 访客 |
| 用例描述 | 访客填写账号密码，系统校验并创建用户 |
| 触发器 | 访客在登录页点击“立即注册”并提交注册信息 |
| 前置条件 | 系统正常运行；当前无登录态；用户名未被占用 |
| 后置条件 | 系统中创建了新的账号信息；提示注册成功 |

**基本事件流**

1. （用户）访客点击注册按钮。
2. （系统）系统展示注册界面。
3. （用户）访客填写用户名、密码、昵称并提交。
4. （系统）系统校验格式与用户名唯一性，通过后写入用户数据并提示注册成功。

**扩展事件流**

- （异常处理）4a、用户名已存在  
  （系统）1、提示注册冲突，停留在注册页等待修改。
- （异常处理）4b、格式不合法（用户名为空、密码过短等）  
  （系统）1、在相应输入框旁提示，不创建账号。

**补充约束**

1. 访客输入的密码应以星号等方式隐藏。
2. 密码在服务端以哈希存储，不以明文保存或回显。

**UC-02 用户登录/登出**

| 项目 | 内容 |
|---|---|
| 用例名称 | 用户登录/登出 |
| 用例编号 | UC-02 |
| 需求ID | REQ-02 |
| 关联子系统 | M1 用户与权限管理 |
| 关联操作 | OP-003 `POST /user/account/login`；OP-004 `POST /admin/account/login`；OP-005 `GET /user/personal/info`；OP-006 `GET /user/account/logout` |
| 参与者 | 访客、注册用户、管理员 |
| 用例描述 | 校验凭据并签发 JWT；登出使会话失效 |
| 触发器 | 用户或管理员在登录页提交账号密码；或已登录用户点击退出 |
| 前置条件 | 登录时系统中已存在相应账号；登出时当前为已登录状态 |
| 后置条件 | 登录成功后进入已登录态并按角色展示入口；登出后回到未登录态 |

**基本事件流**

1. （用户）访客填写账号和密码并点击登录。
2. （系统）系统校验凭据，签发 JWT，前端保存令牌进入已登录态，按 role 展示导航。
3. （用户）用户可请求当前个人信息以确认登录态。
4. （用户）用户或管理员点击退出登录。
5. （系统）系统使令牌失效，返回未登录状态。

**扩展事件流**

- （可选）1a、管理员使用管理员登录入口  
  （系统）1、校验通过后进入管理后台权限。
- （异常处理）2a、账号或密码错误  
  （系统）1、给出明确失败提示（不泄露具体是哪一项错误），中止登录。
- （异常处理）2b、令牌过期后访问需鉴权接口  
  （系统）1、返回 401，前端引导重新登录。
- （可选）4a、用户取消退出  
  （系统）1、保持已登录状态。

**补充约束**

1. 密码输入应以星号等方式隐藏。
2. 支持本地多账号切换：当前标签页可保存多个令牌，活跃账号互不覆盖。

### 3.2 对外接口需求

#### 3.2.1 用户界面

- 输入设备：键盘，鼠标。
- 输出设备：显示器。
- 输出格式：网页。
- 界面风格：用户界面友好，适配显示器比例，导航清晰，分区明确。
- 警告呈现：对于操作出现异常的情况，交互界面需要提示用户出错的信息。
- 主要页面：首页、视频详情、搜索、订阅动态、创作中心、直播列表与直播间、个人中心、私信、管理后台（待审、举报）。

#### 3.2.2 硬件接口

无。本系统不直接与专用硬件设备（如读卡器、传感器、打印机等）交互。客户端运行所需的标准输入/输出设备及网络设备由操作系统和浏览器管理。

#### 3.2.3 软件接口

- 操作系统：支持 Windows、Linux 等常用操作系统。
- 数据库：MySQL 8.0，通过 JDBC 访问。
- 对象存储/文件系统：视频、封面、头像保存于本地 `uploads/` 目录，经 HTTP 访问。
- 可选流媒体：SRS（RTMP/HLS），用于直播推流演示。

#### 3.2.4 通讯接口

- 通信协议：TCP/IP。
- 应用协议：HTTP/HTTPS，RESTful API。
- 鉴权：请求头 `Authorization` 携带 JWT（支持 Bearer 或直接 token）。
- 统一响应：`{ code, message, data }`，`code=200` 表示成功。

### 3.3 性能需求

#### 3.3.1 静态数值要求

- 支持的终端数量：课程演示与小组并发访问，不以全校规模为设计目标。
- 支持的并发用户数：满足小组并发演示与基本访问。
- 要处理的信息数量和类型：以文本、图片（封面/头像/表情）和视频文件为主。

#### 3.3.2 动态数值需求

- 对于 95% 的设备，应在 3.0 秒内完成页面切换。
- 对于 90% 的翻页点击，应在 2.0 秒内完成新页面的加载。
- 对于 90% 的页面更新（如发布评论、关注、标记已读等），应在 1 秒内处理。
- 对于 95% 的搜索，应在 3 秒内返回搜索结果。
- 数据的上传和下载时间：由网络状况和文件大小决定；视频上传上限 500MB。

### 3.4 设计约束

#### 3.4.1 标准合规性

- 为保证用户账号安全，密码须哈希存储，登录传输使用 HTTP 环境下的基本防护（部署阶段建议 HTTPS）。
- 未注册/未登录用户不得评论、赞踩、上传、私信。
- 新上传视频必须经过管理员审核后才能进入公开列表。

#### 3.4.2 硬件限制

暂无专用硬件限制。服务端建议 2 核 CPU、4GB 内存、20GB 以上存储。

### 3.5 软件系统属性

#### 3.5.1 可靠性

1. 交付前应进行充分的测试，包括单元测试、集成/API 测试、端到端测试。
2. 采用模块化开发、接口设计规范，达到高内聚低耦合。
3. 对常见异常（网络、鉴权、资源不存在）有明确提示，避免未处理崩溃导致数据明显损坏。

#### 3.5.2 可用性

1. 建立错误和异常处理机制，例如日志记录，以便排查。
2. 执行合理的备份和存储策略，确保用户、视频和评论等数据可恢复。
3. 在部署与课设演示时段内，系统可被正常访问与操作。

#### 3.5.3 安全

- 密码不以明文存储或回显。
- 需保留关键操作与错误日志。
- 按角色控制上传、审核、复审等敏感接口。
- 未授权访问返回 401/403，不泄露多余账号信息。

#### 3.5.4 可维护性

整个系统的各个功能高度模块化，实现清晰的模块接口。数据库表结构与用例编号可追溯，方便以后的系统维护。

#### 3.5.5 可移植性

服务端与数据层在常见 Web 与 MySQL 环境下可重新部署；客户端通过现代浏览器访问，不绑定单一专有客户端形态。

### 3.6 其他需求

#### 3.6.1 逻辑数据库要求

**用户信息**

- 使用频率：中等
- 应包含：用户 id（主键）、用户名（unique, not null）、密码哈希、昵称、头像、简介、角色

**视频信息**

- 使用频率：高
- 应包含：视频 id（主键）、作者 id（外键）、标题、简介、文件路径、封面、状态、可见性、创建时间

**评论、赞踩、订阅、播放历史、通知、私信、直播间、举报表**

- 字段与约束以满足 UC-01～UC-15 为准，详见《软件详细设计说明书》与 `database/database.sql`。

#### 3.6.2 需求的优先次序和关键程度

| 优先级 | 用例 | 说明 |
|---|---|---|
| 高 | UC-01、UC-02、UC-04、UC-06、UC-15 | 账号、播放、上传审核为系统主链路 |
| 高 | UC-03、UC-05、UC-09、UC-10、UC-11、UC-12 | 资料、历史、关注、评论赞踩、搜索为高频能力 |
| 中 | UC-07、UC-08、UC-13、UC-14 | 举报、直播房间、通知、私信为完整业务闭环 |
| 低 | 直播真实推流画面 | 本版本演示占位，不计入核心验收 |
